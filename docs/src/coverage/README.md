# Coverage

`monkey-c-coverage` measures **function-level** test coverage for Monkey C.
Connect IQ has no native coverage support, so coverage is obtained by
rewriting the source before compilation:

1. `instrument` parses each file with `monkey-c-parser` and splices a
   `AutoGeneratedCov.hit(N);` call directly after the opening brace of every
   function body, writing the rewritten copies, a generated
   `AutoGeneratedCov.mc` runtime, and a `coverage-manifest.tsv` (id, line, file,
   function) into an output directory. Untouched code stays byte-identical — the
   same byte-range patching `monkey-c-linter --fix` uses. Input paths are
   mirrored under the output directory relative to the project root (the
   nearest ancestor holding `manifest.xml`), so `instrument` must be run from
   inside a Connect IQ project; this is what lets two files sharing a name in
   different directories land at distinct destinations instead of colliding,
   regardless of which subdirectory the tool is invoked from or whether an
   input is passed more than once. With no files or directories given,
   `instrument` covers the whole project, skipping `{root}/bin` where the
   compiler and Monkey C Optimizer write build artifacts. `--out` (and
   `report`'s `--dir`) both default to `{root}/bin/coverage`, so the tool can
   be run from any subdirectory of the project without any arguments.
   Declarations annotated with `(:test)` are left uninstrumented so test code
   never counts toward its own coverage; `--exclude-annotation` adds further
   annotations (e.g. ones set via a jungle's `excludeAnnotations`) to skip the
   same way.
2. `instrument` also writes `{out}/coverage.jungle`, a copy of the project's
   jungle file (`--jungle`, defaulting to `{root}/monkey.jungle`) with
   `project.manifest` repointed at the real `manifest.xml` — it isn't
   mirrored into `out` the way `.mc` sources are, so the original relative
   reference no longer resolves once the jungle moves — and a `.` added to
   every `sourcePath` that doesn't already scan it, so `monkeyc` also picks
   up `AutoGeneratedCov.mc` sitting directly in `out`. `resourcePath` entries
   are copied as-is and are **not** rebased, so a project with resources
   needs to fix those up by hand until that's handled here too.
3. Compile the instrumented directory with `monkeyc --unit-test` and run the
   tests with `monkeydo … -t`, capturing the console output to a log file.
   The runtime prints one line, exactly `COVHIT <id>`, the first time each
   function runs.
4. `report` joins that log against the manifest in the output directory and
   prints per-file coverage with the names of every function that never ran.
   Its location is a positional argument; pass `-` to read it from stdin
   instead, so `monkeydo`'s output can be piped straight in.

```sh
monkey-c-coverage instrument
monkeyc -f bin/coverage/coverage.jungle -d <device> -o bin/coverage/cov.prg -y key --unit-test
```

Then either pipe straight into `report`:

```sh
monkeydo bin/coverage/cov.prg <device> -t | monkey-c-coverage report -
```

Or capture the log to a file first, e.g. to keep the raw output around:

```sh
monkeydo bin/coverage/cov.prg <device> -t | tee bin/coverage/run.log
monkey-c-coverage report bin/coverage/run.log
```

> _**NOTE**: The simulator needs to be running when executing `monkeydo`_

Coverage is **function-level only**: it answers "which functions never
execute under the test suite", including functions reached indirectly that
static reference scanning cannot see. It does **not** measure statement or
branch coverage — a single 200-line function that runs once counts as fully
covered, so read a high percentage as "these functions ran", not "these
lines ran".

The simulator may reinitialize module state between unit tests, so the
first-hit deduplication restarts per test and ids can repeat in the log;
`report` deduplicates while joining. Only lines that are exactly
`COVHIT <id>` are counted, so anything else the simulator interleaves in the
console is ignored.
